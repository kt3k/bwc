# テストプレイヤー

AI のサブエージェントにゲームを遊ばせて感想を集めるときは、この
メモのプレイヤー像と手順を使う。サブエージェントへの指示には
「共通の特徴」をそのまま入れ、そのうえで「遊び方の癖」を 1 人ずつ 変える。

## 共通の特徴

テストプレイヤーは全員、次の好みを持つ。

- **単純作業を嫌う。** 何もない道を長く歩く、同じことを何度も繰り返す、
  といった時間にすぐ飽きる。
- **不思議なもの、ユニークなものに興味を持つ。** 変わった物、思わぬ
  ふるまいをする生き物、何か秘密が隠れていそうな場所に引き寄せられる。
- **ルールが複雑すぎることを嫌う。** 覚えることが多い、説明を読まないと
  分からない、例外だらけ、といった仕組みは楽しめない。
- **単純なルールから複雑な状況が生まれることを喜ぶ。** 少ないルールが
  組み合わさって、思いがけない展開や工夫の余地が生まれると嬉しい。

## 遊び方の癖 (1 人ずつ 1 つ)

共通の特徴に加えて、プレイヤーごとに癖を変えると感想がばらける。

| 名前                 | 癖                                                                     |
| -------------------- | ---------------------------------------------------------------------- |
| THE WANDERER         | 面白そうな方へ気の向くまま歩く                                         |
| THE TINKERER         | 物という物に触り、space や道具をあちこちで試して仕組みを知りたがる     |
| THE STORY SEEKER     | 人や看板、町を探し、物語や目的のヒントを求める                         |
| THE IMPATIENT ONE    | 1 か所に長居しない。すぐ何も起きなければ移る。いつ・なぜ飽きたかを言う |
| THE CREATURE WATCHER | 動物を観察し、追いかけ、ぶつかったり物を置いたりして関わり方を試す     |
| THE MAP READER       | ミニマップで変わった形や目印を探して向かい、行く価値があったか判定する |

## 手順

1. ゲームをビルドして配信する: `deno task build`、`deno task serve` (port
   8000)。
2. 開始地点を選ぶ。WILDS (static/map の block_*、i >= 2000, j >= 0) の
   歩けるセルからランダムに、四方も歩けるところを選ぶ。
3. サブエージェントを並べて起動する。文字で遊ぶ人と画像で遊ぶ人を半々に
   する。指示に入れること:
   - 共通の特徴と、その人の癖。
   - ソースは読まず、ファイルも変えず、画面だけを見て遊ぶこと
     (tools/playtest_looks.json も読まない)。
   - ハーネスの使い方 (下記)。最初の 1 回だけ開始地点を渡す。
   - 1 回の呼び出しは歩き 15 マス程度までにし、毎回、出てきた画面
     (文字の地図、またはスクリーンショット) を見て判断すること。30〜40 回
     ほど遊ぶこと。
   - 文字で遊ぶ人には、終わったら `--stop` でゲームを閉じること。
   - 報告の形式 (下記)。
4. 報告を集計し、共通して出た不満・喜びから改善案を考える。

## ハーネスは 2 つ: 文字で遊ぶ人と、画像で遊ぶ人

テストプレイヤーは 2 種類に分ける。6 人なら 3 人ずつ。

- **文字で遊ぶ人** (tools/playtest_text.mjs): 画面を文字の地図で受け取る。
  物は見た目の言葉で書かれるので、小さな絵の読み違いがなく、目標に
  気づいたか・解けたかを正しく測れる。画像を読まないので、軽いモデルでも
  遊べる。
- **画像で遊ぶ人** (tools/playtest.mjs): 今まで通りスクリーンショットで
  遊ぶ。絵がそれと伝わるか (鐘を「池の中の箱」と読む、など) は、この人たち
  にしか分からない。

## ハーネス: tools/playtest_text.mjs (文字)

プレイヤーごとにゲームを 1 つ開いたまま裏に置き、呼び出しのたびに手順を
送る。動いた物はそのまま、呼び出しの合間は時間が止まっている (AI が考える
間に世界が進まない)。1 時間呼ばれなければ閉じる。`--stop` ですぐ閉じる。
ゲームは URL に `?playtest` を付けたときだけ、画面の中身をデータで返す口
(game/playtest-hook.ts) を開く。

```
node tools/playtest_text.mjs <player-name> "<steps>" [start i,j]
node tools/playtest_text.mjs <player-name> --stop
```

手順は下の画像のハーネスと同じ (`up:N` など、`space`、`tool`、`wait:MS`)。
違うのは 2 つ。`map` はミニマップを文字で出す (1 文字 4×4 マス)。`look` は
スクリーンショットも撮る。

呼び出しのたびに出すもの:

- 画面の格子 (27×27 マス)。自分が `@` で 0,0。地形は記号 (`.` 草地、`~` 水、`#`
  岩、`&` 木、など)、上に乗る物は英字。
- 凡例。物は見た目だけの言葉で書く (tools/playtest_looks.json)。同じ
  マスに重なった物、空中や地面のエフェクト (鳥など)。
- 言われたこと (メッセージ、吹き出し)。
- 手順の間に動いた物、見えてきた物、消えた物、見た目が変わった物。
- 位置、コイン、りんご、場所名、SPACE の絵。

### 見た目の言葉: tools/playtest_looks.json

地形・置き物 (状態ごとの絵)・アイテム・生き物の、すべての絵に、見た目
だけを書いた短い英語を付ける (例:
`a grey square slab with a dark ring
pattern`)。何のための物か、どう動くかは書かない
(button、goal、puzzle、 pushable
などは使わない)。書かれていないと答えを教えることになり、「自分で
気づくか」が測れなくなる。

- 絵を足したり変えたりしたら、ここにも足す。`deno test` の
  tools/playtest_looks.test.ts が、書き漏れと、用途を明かす言葉を見つける。
- 地形には格子の記号 (`sym`) も付ける。物の英字と重ならないよう、地形は 記号と
  `v` (下向き矢印の床) だけを使う。

## ハーネス: tools/playtest.mjs (画像)

1 回の呼び出しでゲームを開き (そのプレイヤーのセーブから再開)、手順を
実行し、画面の文字 (メッセージ、吹き出し) を出力して、最後に
スクリーンショットを撮って閉じる。セーブとスクリーンショットは `$PLAYTEST_DIR`
(既定は /tmp/bwc-playtest) の下に、プレイヤー名ごとに残る。

```
node tools/playtest.mjs <player-name> "<steps>" [start i,j]
```

手順 (空白区切り):

- `up:N` `down:N` `left:N` `right:N`: N マス歩く。ぶつかると押す・話す。
- `space`: 掘る、跳ぶ、選んだ道具を置く (画面下の SPACE の絵が今の動作)。
- `tool`: 置く道具を切り替える (なし → りんご → 魚 → なし)。
- `map`: ミニマップをタップする (大きく開く / 閉じる)。
- `wait:MS`: 待つ (1000 = 1 秒)。
- `shot`: 途中でスクリーンショットを撮る。

最後に位置 (ワールド座標)、コイン、りんご、場所名を出力する。

## 報告の形式

日本語で、次の見出しで書かせる。

1. 行動の記録: 何をして何を見つけたかの短い時系列 (座標つき)。
2. 面白かった/不思議だった瞬間: それぞれ、なぜ惹かれたか。
3. 退屈・単純作業だと感じた瞬間: それぞれ、何が退屈だったか。
4. 分からなかったこと・迷ったこと。ルールが複雑すぎると感じたところ。
5. バグらしきもの (座標と起きたこと)。
6. 評価 (1-5): 楽しさ、好奇心をくすぐる度、単純作業の少なさ、
   ルールの分かりやすさ、また遊びたい度。
7. こうなったらもっと楽しい: 具体的な要望 3 つ。

## 読み方の注意

- AI は 1 操作に数秒かかり、タイミングの厳しい仕掛けは人間より難しく 感じる。
- 画像のハーネスは呼び出しのたびにゲームを開き直す。置いた物、生き物の
  位置、道具の選択は呼び出しをまたぐと戻る。これをバグと報告されたら 割り引く
  (文字のハーネスでは戻らない)。
- AI はスクリーンショットの細部を見落とすことがある。「気づかなかった」
  という感想は、見た目で伝わっていない合図として扱う。
